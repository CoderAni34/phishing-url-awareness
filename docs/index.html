THE SIX SIGNALS

What’s in a link?

Small details worth noticing.
Each has legitimate uses, too.

01

The @ symbol

Text before @ in a URL’s authority can disguise the destination. This broad check also flags @ in a path or query.

02

A very long URL

More than 100 characters can make a link harder to read. Plenty of legitimate links are long, too.

03

A numeric-looking host

Four groups of digits can hide a familiar name. The workbook rule matches IPv4-style text; it doesn’t validate the address.

04

Lots of hostname parts

Five or more dot-separated parts can make a host confusing. Large services sometimes use many parts legitimately.

05

The xn-- marker

Punycode can represent international domain names, including look-alike letters. International names aren’t inherently suspicious.

06

Plain HTTP

HTTP doesn’t encrypt traffic. HTTPS adds encryption, but doesn’t prove that the site itself is honest.

This is Aniket’s web demo for the EWB AI Powered Cyber Security Internship. The original Python project and recorded tests are available on GitHub.

The demo checks text only. No DNS lookups, website visits, redirects, malware scans or reputation checks. The browser parser is a small adaptation of the Python workbook rules, not a full URL validator. Encoded symbols, Unicode look-alikes and IPv6 are outside these six checks. No history is saved.
